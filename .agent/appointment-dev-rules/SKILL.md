# 宠物门店预约系统 AI 开发约束规则（加载入口）

本 Skill 封装本项目的 AI 辅助开发约束。**任何一次写代码 / 加测试 / 提交前，先读 `.agent` 根目录的 `README.md`（总索引），再按本次改动类型跳到对应文件夹下的文件。**

约束按"通用 / 后端 / 前端"分文件夹存放，按需加载：

1. **`general/principles.md`** —— 总纲：状态机是唯一裁判、同一份业务记录、闭环优先、问题沉淀机制、AI 行为准则。**每次任务开始前都过一遍。**
2. **`general/feature-gate.md`** —— **新增规则一：逐功能点测试闸门**（开发完一个功能点 → 立刻测 → PASS 才能进入下一阶段）。
3. **`general/unit-test.md`** —— **新增规则二：模块单元测试强制**（模块清单、写法、必测不变量矩阵、覆盖率 ≥85%）。
4. **`backend/constraints.md`** —— Go 工程结构、本题专属铁律：金额 `int64` 分 9900、名额原子更新、5 分钟占位、2 小时取消线、支付幂等、迟到回调不复活、取消×核销唯一结果、退款状态独立、核销三条件、未到店不自动退款、收入只认已完成服务记录。
5. **`backend/tech-stack.md`** —— MySQL 真相源 + Redis 缓存/去重、事务、Cache-Aside 写失效、迁移。
6. **`frontend/code-style.md`** —— 目录/命名/状态单一来源/金额展示换算/防越权渲染/禁止项。
7. **`frontend/ui-style.md`** —— 商务蓝视觉、状态色徽章、设备框、移动端优先、反馈与状态可视化。
8. **`frontend/permission.md`** —— 五角色与 15 个页面的分配、`requireRole`、数据隔离、越权演示。
9. **`general/acceptance.md`** —— 通用门槛 + 5 个必演场景断言 + 收店核查金额口径。
10. **`general/git-convention.md`** —— `[类型] [版本号] [编号] 描述`；未接入 meegle 时编号用 SRS 章节号 / FR 编号。
11. **`workflow/feature-points.md` / `workflow/progress.md`** —— 功能点顺序、必写单测、断言、前置依赖与进度追踪。

配套文件：**`general/issue-log.md`**（与本目录同处）—— 任何 bug / 竞态 / 歧义先写再修，顶部预置 P1–P8 预防性坑。

## 执行纪律（每次开发任务开始前）

1. 读 `README.md` → 确认本次改动类型（后端 / 前端 / 通用），加载对应文件夹下的文件。
2. 确认本次改动对应的**预约状态机迁移**与**名额占用语义**（没有合法迁移就不做）。
3. 从 `workflow/feature-points.md` 取**一个**功能点；确认前置功能点全部 `已通过`。
4. 写实现 → **同步写该模块单元测试**（`general/unit-test.md`）→ **立刻跑本功能点闸门**（`general/feature-gate.md`）→ `PASS` 后写证据、更新 `progress.md`、按 `git-convention.md` 提交。
5. **闸门 FAIL**：先写 `issue-log.md`，只修本功能点，原闸门重跑；**禁止开始下一个功能点或进入下一阶段**。
6. 遇到未预期行为：先追加 `issue-log.md` 再修复，最后回填"是否上升为约束"。
7. 提交前过 `general/acceptance.md` 通用门槛与相关场景断言。

> 需求锚点：SRS V1.0（`题目02-宠物门店预约服务与取消退款-需求规格说明书.docx`）+ 题目原文 8 条规则 + 状态机；原型：`prototype/宠物门店预约系统-角色页面原型.html`。
> 题目明确：**须执行第一部分全部要求，不能只交名额抢占功能**；不做优惠、会员、排班优化、多店结算、档案编辑、争议退款裁决、未到店自动退款。
