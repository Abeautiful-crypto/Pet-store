## 闸门记录模板（`workflow/gate-records/<ID>.json`）

```json
{
  "feature": "F3.2",
  "result": "PASS",
  "at": "2026-11-13T10:20:00+08:00",
  "checks": [
    {"name": "gofmt -l", "cmd": "gofmt -l .", "exit": 0},
    {"name": "go vet", "cmd": "go vet ./...", "exit": 0},
    {"name": "功能点单测", "cmd": "go test -race -count=1 -run TestSlot ./internal/service", "exit": 0}
  ],
  "tests_hit": 8,
  "requires": ["F3.1"],
  "notes": "前置 F3.1 已通过；无遗留 FAIL"
}
```

原型阶段（尚无 Go 代码）时，`checks` 记录文档/页面逐项核对的结论与依据章节，`tests_hit` 记为 0 并注明"原型核对"。

## 纪律

- 一次只改一行状态；改状态前先确认对应证据文件存在且为 `PASS`。
- 证据文件不得手改或伪造；手改等同于伪造测试通过（违反 `general/principles.md` 第 1 节）。
- `未开始` 直接跳到 `已通过`、或 `闸门失败` 期间推进别的阶段，均为违规。
