# 06 · 验收标准

> 每次完成功能自测、提交前遵循本文件。通用原则见 `general/principles.md`，后端铁律见 `backend/constraints.md`，逐功能点闸门见 `general/feature-gate.md`。
> 场景来源：SRS 第 10 章"必演工作场景与验收用例"（题目 2.6 原文）。

## 1. 通用门槛（每次提交前必过）

- [ ] 构建通过（`go build ./...`；前端原型可正常打开且角色切换可用）
- [ ] `gofmt` / `go vet` 无输出（前端无 lint 错误）
- [ ] 改动涉及的核心不变量有单测覆盖（名额、幂等、取消×核销互斥、越权、收入口径）
- [ ] 相关单测通过（`go test -race -count=1 ./...`）
- [ ] **本功能点闸门 `PASS` 且证据已写入 `workflow/gate-records/`**（新增规则一）
- [ ] **涉及模块全部有单元测试**（新增规则二）

## 2. 五个必演场景断言清单

每个场景的"通过" = 预约主记录状态 + 名额 + 支付/退款流水 + 服务记录**四项同时成立**。

| 场景 | 操作步骤 | 验收断言（必须全部满足） |
| --- | --- | --- |
| **SC-01 正常接待** | 店长发布时段 → 用户预约付款 → 前台核销 → 服务开始、完成 → 用户与店长查询 | 状态顺序 待支付→已确认→已核销→服务中→已完成；收入恰好记一次 9900 分；用户与店长看到的状态一致 |
| **SC-02 名额循环** | 并发预约抢占 → 未付款超时或用户取消 → 名额恢复 → 新用户预约成功 | 任一时刻 `occupied_count ≤ 3`；并发抢最后 1 名额恰好 1 人成功；释放只发生一次；释放后新用户可成功预约；同一宠物同一时段不重复占名额 |
| **SC-03 取消分支** | 提前取消自动受理；临近开始时客服分别批准、拒绝；退款失败后重试 | ≥2h 自动受理 + 全额退款；<2h 原因必填且待审核期间名额保持、禁止核销；批准/拒绝结果用户各自可见；退款失败→重试成功全过程预约不复活、名额不恢复 |
| **SC-04 门店现场冲突** | 同一预约取消与核销并发、重复核销、非本店员工操作 | 并发后只有一个合法状态，冲突留痕；重复核销/完成幂等且收入仍只记一次；非本店员工操作被拦截且不改动任何记录；金额记录无重复无丢失 |
| **SC-05 收店核查** | 同一天包含已服务、取消退款、未到店、退款失败四种记录 | 四类记录可分别核查；已收款/已退款/未退款金额可逐笔反查；已付款未被全部计作已完成服务收入 |

## 3. 收店核查金额口径（SC-05 硬证据）

| 指标 | 演示值（分） | 口径 |
| --- | --- | --- |
| 已收款 | 39600 | 支付成功的 4 笔 × 9900 |
| 已退款 | 9900 | 退款单状态"退款成功"的金额 |
| 未退款金额 | 29700 | 已收款 − 已退款；含退款失败待跟进、未到店未退款 |
| **已完成服务收入** | **9900** | 仅"已完成"服务记录的 `revenue_fen` 合计 |

> **规则 8 禁止的错误口径**：把 4 笔已付款全部计作已完成服务，会虚增收入 29700 分。金额三分类必须能从支付单 + 退款单 + 服务记录逐笔反查。

## 4. 自动化验收

- 交付时提供**验收 Skill / 一键脚本**，跑完 5 个场景并输出 PASS/FAIL 与每场景断言明细（对齐 `workflow/feature-points.md` 阶段 5）。
- 任何一次"完成功能"后，先跑该点相关场景断言，再提交；**闸门 FAIL 不得进入下一功能点**（`general/feature-gate.md`）。
- 原型阶段无脚本时，按 `prototype/宠物门店预约系统-角色页面原型.html` 的 15 个页面逐页点击核对，并把结论写入闸门证据。
