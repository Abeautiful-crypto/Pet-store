# 07 · Git 提交规范

> 每次提交前遵循本文件。格式与类型定义沿用参考范本的 `commit-convention.md`（飞书 meegle 体系）。

## 1. 格式

```
[类型] [版本号] [需求/Bug编号] 描述
```

## 2. 类型

| 类型 | 用途 |
| --- | --- |
| feat | 新增功能需求 |
| fix | 修复 Bug |
| hotfix | 线上紧急修复（事后补编号） |
| opt | 优化（性能、代码质量、重构） |
| docs | 文档变更 |
| test | 测试相关 |

## 3. 必填规则

| 类型 | 版本号 | 编号 | 说明 |
| --- | --- | --- | --- |
| feat | 必填 | 必填 | 新功能必须关联需求编号 |
| fix | 必填 | 必填 | Bug 修复必须关联编号 |
| hotfix | 必填 | 可选 | 紧急修复，编号可事后补 |
| opt | 必填 | 可选 | 优化可不关联编号 |
| docs | 可选 | 可选 | 文档变更可都不带 |
| test | 可选 | 可选 | 测试相关可都不带 |

## 4. 示例（本项目）

- `[feat] [v1.0.0] [FR-02] 实现同一宠物同一时段唯一有效预约`
- `[feat] [v1.0.0] [FR-04] 未付款预约 5 分钟占位与超时释放`
- `[fix] [v1.0.0] [规则6] 修复取消与核销并发双成功`
- `[test] [v1.0.0] 补充名额抢占并发 -race 单测`
- `[docs] 更新 AI 开发约束规则`

## 5. 通用规则

- 描述用**中文**，简洁明了；版本号 `v{主}.{次}.{修订}`，如 `v1.0.0`。
- 编号规则：本项目为作业/演示场景，**未接入 meegle**，编号改用 SRS 章节号 / FR 编号 / 规则编号，并在提交说明里注明"未接入 meegle"。
- 一次 commit 只含**一个类型**；混合变更拆多次提交。
- **禁止用 AI 自动编造不存在的编号**。
- 提交前必须已完成本功能点闸门 `PASS`（`general/feature-gate.md`）；闸门失败的代码不得提交。
