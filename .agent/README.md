## 一页速查（开发前默念）

1. 这次改动对应**预约状态机**哪条迁移？——没有就不做（`general/principles.md` + `backend/constraints.md`）。
2. 金额是 `int64` 分（9900）吗？名额是原子条件更新吗？——不是就打回。
3. 5 分钟占位、2 小时取消线、取消与核销并发唯一结果、退款状态独立——都守住没有？
4. 前台只核销**本店 + 已确认 + 无待处理取消申请**的预约？用户只能选自己的宠物？
5. **写完立刻测这个功能点了吗？闸门 PASS 了吗？涉及模块都有单测吗？**（`general/feature-gate.md` + `general/unit-test.md`）
6. 已收款 ≠ 已完成服务收入；未到店不自动退款；退款失败不让名额复活。
7. 提交格式 `[类型] [版本号] [编号] 描述`——中文、一类型一提交（`general/git-convention.md`）。

## 前提假设（沿用范本技术栈，落地代码前需确认）

- 后端：**Go 1.22**；金额 `int64` 分，全程禁浮点。
- 存储与缓存：**MySQL 8.0+ 真相源 + Redis 7+ 缓存/去重**（沿用参考范本的项目约定；本项目需求文档未指定技术栈，如改用其他选型，先更新 `backend/tech-stack.md` 再动手）。
- 前端：当前为 `prototype/` 下的 HTML+JS 单文件原型；后续落地框架按 `frontend/code-style.md` 目录约定。
- 项目当前处于**需求基线 + 原型已完成、业务代码尚未落地**的阶段；`.agent` 中的模块清单是落地时的工程结构约定。

> 题目明确：**须执行第一部分全部要求，不能只交名额抢占功能**；不做优惠、会员、排班优化、多店结算、档案编辑、争议退款裁决、未到店自动退款。
