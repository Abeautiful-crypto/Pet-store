# 04 · 前端 UI 与样式规范

> 视觉与交互层约束。以已交付的 `prototype/宠物门店预约系统-角色页面原型.html` 为视觉基准：商务蓝、浅色卡片、状态色徽章、设备框线框。代码层见 `frontend/code-style.md`，权限见 `frontend/permission.md`。

## 1. 设计语言

| 项 | 约定 |
| --- | --- |
| 主色 | 商务蓝 `#1565C0`；标题深蓝 `#1A237E`；浅色底 `#F5F7FA`；边框 `#DDE4EE` |
| 背景 | 浅色（跟随 IDE light 主题），白底卡片 + 深色文字，禁止深色面板 |
| 圆角 / 阴影 | 圆角 8–12px；轻投影 `0 1px 4px rgba(20,40,80,.04)`，不用渐变/发光 |
| 强调 | 关键数字（9900 分、39600 / 29700 口径）用加粗或主色，不用满屏红 |

## 2. 状态色徽章（全站统一，与 SRS 5.4 状态机一致）

| 状态 | 颜色 | 用途 |
| --- | --- | --- |
| 待支付 · 占位中 | 橙 `#F9A825` | 5 分钟占位倒计时 |
| 已确认 / 已核销 / 服务中 | 蓝 `#1565C0` | 有效预约与接待进度 |
| 取消审核中 | 紫 `#7B1FA2` | 名额保持、禁止核销 |
| 已完成 | 绿 `#00897B` | 收入已记一次 |
| 已取消 / 已关闭 | 灰 `#78909C` | 名额已释放 |
| 未到店 / 退款失败待跟进 | 红 `#E53935` | 不自动退款、需客服跟进 |

> 同一状态在所有角色页面必须用同一颜色与同一文案，避免用户端与店长端出现分歧。

## 3. 设备框与响应式

- **用户端**（U1–U4）用手机框（约 330px 宽）；**前台 / 客服 / 店长 / 渠道**（F/C/M/P 页）用桌面框。
- 用户端以 375px 设计稿为基准；断点：≤480 单列，≥768 可双列；触控目标 ≥44px。
- 页面顶部保留设备栏（地址），便于讲解时区分"这是哪一端的页面"。

## 4. 组件化

- 复用组件：时段卡、预约行、状态徽章、按钮组、Toast、确认弹窗、共享记录条、业务 Skill 校验条、页面规则/出口区。
- 组件只接收 props / 状态，不越权发起写操作（写操作走 `api/` + `requireRole`）。
- 每个页面固定四段结构：**页面标题与职责 → 设备线框 → 业务 Skill 校验条 → 页面规则与出口**。

## 5. 用户反馈（强制）

- 每次操作（预约、支付、取消、审核、核销、登记、标记未到店、时段发布、退款重试）**必须有明确反馈**：成功 toast、失败明确原因（"名额不足""时段已开始""存在待处理取消申请，禁止核销""越权：未做任何改动"）。
- 危险操作（取消、退款、标记未到店）弹确认；幂等按钮在请求进行中禁用，防重复点击。
- 加载态用骨架屏或局部 loading，不整页白屏。

## 6. 状态可视化

- 服务进度用 4 段进度条（已确认 → 已核销 → 服务中 → 已完成）。
- 店长日清页用指标卡展示四个金额，并保留逐笔对账表（A1–A4 四种结局）。
- 页面底部"业务 Skill 校验条"用紫色标记，直观展示本页触发的约束（名额 / 预约时间 / 取消政策 / 服务进度 / 退款）。

## 7. 禁止项

- 禁止无反馈的静默失败；禁止把错误吞进 `catch` 不提示。
- 禁止为"好看"牺牲可读性（浅底深字，保证对比度）。
- 禁止不同页面各写一套主题色；统一走 `styles/` 设计变量。
- 禁止装饰性渐变、阴影堆叠、深色背景面板（与 light 主题冲突）。
